## command 检查

执行一次。退出码 0 表示命题成立，1 表示不成立（把反例打印到标准输出），其他退出码表示检查本身出了问题。结构命题和含 `调用` 的具体事实只能用 command 检查。

## trace 检查

执行 `runs` 次，第 i 次设置 `CV_RUN=i`（用作随机种子）和 `CV_TRACE`（轨迹文件路径）。命令运行程序（例如用随机输入驱动它），把运行过程写成轨迹文件，checker 在轨迹上判定公式。**每条时序命题至少要有一项 trace 检查。** 同一个脚本可以给多条命题使用。

轨迹是 JSON Lines 文件，每行一个状态：

```json
{"实体": {"蛇": ["蛇"], "食物": ["f1"]},
 "值": {"长度(蛇)": 3, "头(蛇)": [4, 2], "格子总数": 100, "吃到(蛇,食物)": false, "结束(游戏)": false},
 "动作": "右"}
```

- 第 i 个状态记录时刻 i 的位置、数量和状态谓词，以及从时刻 i 到 i+1 这一步中发生的事件谓词（含义为“这一步……”的谓词）和这一步执行的动作。最后一个状态没有后续的一步，它的事件谓词填 false。
- `值` 的键是去掉空格的函数写法，例如 `吃到(蛇,食物)`；参数是实体名或个体编号。零个参数的写名称本身，例如 `格子总数`。
- 谓词的值是 true/false，数量的值是数，位置的值是任意 JSON 值。每个状态都要给出公式用到的全部键。
- `实体` 列出每个实体在这个状态中的个体。实体名作参数时指它唯一的个体，所以给出 `实体` 时，被当作常量使用的实体每个状态都要恰有一个个体。量词在这个列表上取值。不需要量词时可以省略 `实体`。
- “从 S 出发，依次执行 a1…an，之后 Q”这类命题，只在动作序列与句子相符的轨迹上判定，你的脚本要至少有一次运行按句子中的动作序列执行。
- 程序崩溃、脚本出错（退出码非 0）都算作这次运行失败。超时的运行按已写出的部分判定。
