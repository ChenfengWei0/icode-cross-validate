# 你要写出的 `{{ALIGN}}/checks.json`

```json
{
  "bindings": {"长度(蛇)": "snake.py 中 Snake.body 的长度"},
  "checks": [
    {"proposition": "R9", "form": "结构检查", "kind": "command",
     "command": "python3 \"$CV_ALIGN/r9_structure.py\"", "timeout": 60},
    {"proposition": "R4", "form": "插桩加模糊测试", "kind": "trace",

```

- `bindings`：每个声明的名称绑定到代码中的什么，用文字说明。
- `checks`：每条命题至少一项。`form` 是你选的形态名称（测试、交给验证器的逻辑公式、插桩加模糊测试、结构检查等），只写进报告。
- `timeout` 不超过 120 秒；`runs` 不超过 200。
- 命令在 W 中用 `sh -c` 执行，环境变量 `CV_ALIGN` 是你的目录，`CV_W` 是 W。

## command 检查

执行一次。退出码 0 表示命题成立，1 表示不成立（把反例打印到标准输出），其他退出码表示检查本身出了问题。结构命题和含 `调用` 的具体事实只能用 command 检查。

## trace 检查

执行 `runs` 次，第 i 次设置 `CV_RUN=i`（用作随机种子）和 `CV_TRACE`（轨迹文件路径）。命令运行程序（例如用随机输入驱动它），把运行过程写成轨迹文件，checker 在轨迹上判定公式。**每条时序命题至少要有一项 trace 检查。** 同一个脚本可以给多条命题使用。

轨迹是 JSON Lines 文件，每行一个状态：

```json
{"实体": {"蛇": ["蛇"], "食物": ["f1"]},
 "值": {"长度(蛇)": 3, "头(蛇)": [4, 2], "格子总数": 100, "吃到(蛇,食物)": false, "结束(游戏)": false},
 "动作": "右"}
```

- 第 i 个状态记录时刻 i 的位置、数量和状态谓词，以及从时刻 i 到 i+1 这一步中发生的事件谓词（含义为“这一步……”的谓词）和这一步执行的动作。最后一个状态没有后续的一步，它的事件谓词填 false。
- `值` 的键是去掉空格的函数写法，例如 `吃到(蛇,食物)`；参数是实体名或个体编号，只有一个个体的实体两种写法都可以。零个参数的写名称本身，例如 `格子总数`。
- 谓词的值是 true/false，数量的值是数，位置的值是任意 JSON 值。每个状态都要给出公式用到的全部键。
- `实体` 列出每个实体在这个状态中的个体。实体名作参数时指它唯一的个体，所以给出 `实体` 时，被当作常量使用的实体每个状态都要恰有一个个体。量词在这个列表上取值。不需要量词时可以省略 `实体`。
- “从 S 出发，依次执行 a1…an，之后 Q”这类命题，只在动作序列与句子相符的轨迹上判定，你的脚本要至少有一次运行按句子中的动作序列执行。
- 程序崩溃、脚本出错（退出码非 0）都算作这次运行失败。超时的运行按已写出的部分判定。

# 检查要严格，也要测得到

- 严格按声明的接口名检查。接口不存在时命题不成立（退出码 1），不要换别的名字代替：声明的是 `size`，就不能退而检查 `length` 或 `__len__`。
- 随机输入不要回避难的情况：把规模推到明显超过示例（例如容器里放几十个元素），允许重复的值，走到空和满这些边界。不要为了好判定而把输入限制在特殊情况里。
- 每条命题的前件都要真的发生。前件在所有轨迹上都没有成立的命题没有被检验，报告会注明。
- 命题或声明中写了具体的异常类型时，只认这个类型，不要用 `except Exception` 一概而论。
- 事件按调用记录，不要按效果记录：这一步调用了 `push(x)`，“压入”就为真，不管元素有没有真的进去，所以不要用“内部列表变长了没有”来判断压入是否发生。否则丢元素的错误代码会被记成“这一步没有压入”，命题全都成立，等于自己证明自己。
- 数量和位置优先用需求规定的接口观察：需求规定了 `size()`，长度就取它的返回值，不要直接读内部列表，否则 `size()` 写错也查不出来。
- trace 脚本只记录观察到的事实，不要自己判定对错。代码的行为不符合预期时（例如 push 之后个数没有增加），照实写进轨迹，继续运行或正常结束，由 checker 在公式上判定。只有脚本无法继续时才以非 0 退出。脚本提前退出时，所有用它的命题都会失败，看不出究竟违反了哪一条。

写完 `checks.json` 和脚本后，简短回答“已完成”，不要报告检查结果。
