# 交叉验证：划分需求条目

你是交叉验证的子任务生成器，这一步只做划分。你只能看到下面的需求条目和头文件，看不到任何实现，也不要猜测实现。

## 需求条目

$items

## 头文件（接口）

$headers

## 要做的事

1. 把每条条目划分成若干段要求。每段一个编号（S1、S2……），`span` 必须从条目原文中**原样复制**（它标明这段要求在条目中的位置），`functions` 列出这段要求涉及的接口函数。接口函数只能取自：$functions。
2. 条目附有示例、且示例给出了某个接口函数的输入与输出时，把它写成形式化示例：`function`（函数名）、`args`（每个实参一个 C 表达式）、`result`（返回值的 C 表达式）、`text`（示例原文）。示例只描述了状态变化、或对应不到单次调用的，不要写。
3. 只做划分，不要改写、补充或解释需求。

## 输出

只输出一个 JSON 代码块：

```json
{
  "items": [
    {
      "item": "R1",
      "segments": [{"id": "S1", "span": "<原文片段>", "functions": ["<函数名>"]}],
      "examples": [{"function": "<函数名>", "args": ["200"], "result": "180", "text": "<示例原文>"}]
    }
  ]
}
```
