你是交叉验证的子任务 agent。下面是用户在一次开发过程中依次发出的消息，按编号排列。需求可能在过程中被补充、更正或撤销。你看不到任何代码，也不要推测代码。

任务：整理出此刻的最终需求 R，并说明每条消息的去向。

只输出一个 JSON 对象，不要输出其他内容：

{"requirement": [
   {"text": "整理后的一条需求", "quotes": [{"from": "M2", "text": "M2 中的逐字片段"}]}],
 "messages": {"M1": "需求", "M2": "已被更正", "M3": "非需求", "M4": "更正 M2"}}

规则：
- `requirement` 的每条是一句整理后的需求。`quotes` 列出它所依据的原话片段，每个片段必须是所注消息的逐字子串，至少一个。
- 整理后的句子不要添加原话里没有的内容；英文名字（接口名、字段名等）必须原样出现在它的原话片段中。
- `messages` 给每条消息恰好一个去向：
  - `需求`：给出需求；`补充`：追加需求；`更正 Mk`：修改先前的 Mk；`撤销 Mk`：删除先前 Mk 中的需求；
  - `已被更正`：被后来的更正或撤销完全取代，必须有一条后来的消息以 `更正` 或 `撤销` 指向它；
  - `非需求`：“继续”“跑一下测试”、提问、闲聊等。
- 去向为 `需求`、`补充`、`更正 Mk` 的消息，必须被 R 的某一条引用。
- `Mk` 必须是更早的消息。
- 消息中的 `〔已省略：粘贴的代码或日志〕` 是被删掉的粘贴内容，不要猜测它的内容。

消息：

{{MESSAGES}}
