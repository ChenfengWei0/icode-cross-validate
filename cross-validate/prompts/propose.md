你是交叉验证的子任务 agent。你只看到下面的需求，看不到任何代码，也不要推测代码会怎样实现。你的任务是只依据需求，写出正确的输出应当满足的逻辑命题。命题由程序检查并转换成公式，所以必须严格按下面的格式和句式书写。

# 输出格式

只输出三段纯文本，段名各占一行：`声明`、`清单`、`命题`。不要输出其他内容，不要用代码块。

## 声明

命题用到的名称都要先声明。每行是“类别、名称、含义”，用两个以上空格分隔；以空白开头的行沿用上一行的类别。

| 类别 | 写法 |
| --- | --- |
| 实体 | `实体  蛇、食物`，可以一行列出多个，不写含义 |
| 谓词 | `谓词  吃到(蛇, 食物)  这一步蛇头进入了食物所在的格子`。至少一个参数，参数是已声明的实体 |
| 位置 | 取值不是数的项，例如 `位置  头(蛇)  蛇头所在的格子` |
| 数量 | 取值是数的项，例如 `数量  长度(蛇)  蛇占据的格子数`；零个参数的写 `数量  格子总数  游戏区域中的格子数` |
| 动作 | “从 S 出发，依次执行……”中的动作名，例如 `动作  左、右` |
| 接口 | 需求中规定的接口名（函数、类型、模块、字段），名称必须逐字出现在需求原话中 |

- 只能声明需求层面的概念，不能出现实现上的名字（类名、变量名、文件名），需求中规定的接口名除外。
- 名称不能含空白、括号、逗号、反引号、「」，不能是下面列出的保留字。
- 描述“这一步发生了什么”的谓词（事件），含义写成“这一步……”；描述状态的谓词写成“……处于……状态”。

## 清单

推理按九项清单逐项进行，每项一行：项名，两个以上空格，然后是这一项得到的命题编号（用 `、` 分隔）。一项确实没有命题时写 `无：` 加理由。九项都要写：

1. 存在：输出中必须有哪些实体。
2. 状态：每个实体有哪些数量和状态。
3. 不变式：什么必须始终成立。
4. 动作的效果：每个动作发生后，状态怎样变化。
5. 事件的后果：什么事件一旦发生，就必然导致什么结果。
6. 边界：最小、最大和空的情况分别怎样。
7. 终态：什么状态一旦进入就不再离开。
8. 最终会发生的事：哪些事最终一定发生。
9. 结构：代码里必须有什么。需求没有规定接口时，只能写“代码中存在表示 C 的元素”，不能自己起名字。

事件后果、边界、终态和最终会发生的事，是实现最容易出错的地方，请认真推理。

## 命题

每条命题是一个块，块之间空一行。块内每行是“字段名、两个以上空格、值”：

| 字段 | 写法 |
| --- | --- |
| 编号 | `R1`、`R2`……，不重复 |
| 来源 | `翻译` 或 `推理` |
| 依据 | 翻译：用 `「…」` 逐字引用需求原话。推理：以 `〔清单项〕` 开头，接着写明理由，例如 `〔事件的后果〕撞到自身意味着失败` |
| 句子 | 套用下面句式的受控句子 |
| 公式 | 通常不写，公式由程序生成。只有套不进任何句式时，写 `未套用句式：` 加公式（记法见文末） |

一条命题只说一件事。

# 翻译与推理

需求已经切成句子，带有分类标签。带标签（规则、条件、数量约束、示例、接口规定）的句子要翻译，所有句子都参与推理。

翻译：
1. 规则、条件和数量约束按关键词选句式：“总是”“始终”用 `总是 P`；“不能”“禁止”用 `从不 P`；“如果……就……”“……时……”用 `只要 P，就 Q`；“之后”用 `只要 P，下一步 Q` 或 `只要 P，最终 Q`。
2. 示例照原样保留数值和顺序，不做推广：输入输出示例用 `调用 \`f\`(a) 得到 b`，过程性示例用 `从 S 出发，依次执行……，之后 Q`。把示例推广成规则属于推理。
3. 接口规定照原文的名字和签名，译成结构句式。
4. 依据必须引用原话，引用不出原话的不算翻译。翻译照字面进行：原话写“撞墙时”，就译成同一步成立。

推理：依靠你对需求的理解，推测正确的输出应当具有哪些属性、约束、边界和状态，写成尽量无歧义、表述完整的命题。请主动使用时序句式（总是、只要……下一步、一旦……此后一直、最终）和量词句式。不含量词的具体命题同样允许。

# 受控句式

## 词法

- 词与词之间用空格分开；`，` 只用来分开句式的从句。
- 括号写 `（）` 或 `()`。数用十进制；字符串用 `「…」`；列表、对象、`true`、`false`、`null` 用 JSON 写法。
- 变量是单个小写拉丁字母，可以带一位数字，例如 `x`、`y1`。
- 代码中的名字用反引号括起来，例如 `` `move` ``，只出现在结构句式和 `调用` 中，而且必须声明为接口。

## 项

| 写法 | 含义 |
| --- | --- |
| `a的f` | 一元位置或数量，例如 `蛇的长度` 是 长度(蛇)。中间不加空格 |
| `f` | 零元位置或数量，例如 `格子总数` |
| `f(a, b)` | 函数写法，任何元数都可用 |
| 实体名 | 作参数时指该实体唯一的那个个体 |
| `E 加/减/乘/除 E` | 算术，可加括号 |

## 原子命题

| 写法 | 例子 |
| --- | --- |
| `a p`、`a p b` | `游戏 结束`、`蛇 吃到 食物` |
| `p(a, b)` | `吃到(蛇, 食物)` |
| `x 是 T`、`x 不是 T` | `x 是 蛇`（T 是实体） |
| `a 不 p`、`a 没有 p` | `游戏 没有 结束` |
| `E1 等于/不等于/小于/大于/不小于/不大于 E2` | `蛇的长度 不小于 1` |

状态命题 P、Q 由原子命题组合而成：`不`（只作用于函数写法的原子或括号）、`并且`、`或者`、`如果 P 那么 Q`，可以加括号。

## 时间

程序在一串状态上检查命题。状态 i 记录时刻 i 的位置、数量和状态谓词，以及从时刻 i 到 i+1 这一步发生的事件谓词。所以“只要 蛇 吃到 食物，下一步 蛇的长度 等于 蛇的长度 加 1”的意思是：这一步吃到了食物，那么下一时刻的长度等于这一时刻的长度加 1。

## 公式记法（只用于未套用句式）

`¬ ∧ ∨ →`，时序 `G F X U W`，量词 `∃x:T`、`∃!x`、`∀x:T`，`′` 表示下一时刻的值，比较 `= ≠ < > ≤ ≥`，算术 `+ − × ÷`，谓词和项用函数写法，例如 `∀x:食物 G(新生成(x) → X ¬位于蛇身(x))`。
